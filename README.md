# Uvita

An iOS app that tracks UV exposure and models serum vitamin D (25(OH)D) levels using the Diffey pharmacokinetic model. It runs passively in the background, logging UV index every 5 minutes via GPS + Open-Meteo, detects indoor/outdoor state via OpenStreetMap building footprints, and integrates dietary vitamin D from food logs, Apple Health, or manual input.

---

## Requirements

- **Xcode** 15 or later
- **iOS** 16.0+ deployment target (SwiftUI features used throughout)
- **Physical iPhone** strongly recommended - background location and CoreMotion don't work meaningfully in the Simulator
- No external Swift packages or CocoaPods - all dependencies are system frameworks

---

## Project Setup

### 1. Clone / open the project

Open your `.xcodeproj` or `.xcworkspace` in Xcode. If you're starting from scratch with just these Swift files:

1. Create a new **iOS App** project in Xcode (SwiftUI interface, Swift language).
2. Delete the default `ContentView.swift` generated by Xcode.
3. Add all `.swift` files from this repo to the target.
4. Replace the generated `Info.plist` with the one provided, or manually add the keys listed below.

### 2. Bundle identifier & signing

In the project's **Signing & Capabilities** tab:

- Set a unique **Bundle Identifier** (e.g. `com.yourname.uvita`).
- Select your **Team** for code signing.
- Xcode will provision automatically if you have a valid Apple Developer account (free accounts work for personal device testing).

### 3. Info.plist: required permission keys

The following keys must be present. They're already in the provided `Info.plist`:

| Key | Purpose |
|-----|---------|
| `NSLocationAlwaysAndWhenInUseUsageDescription` | Background UV tracking |
| `NSLocationWhenInUseUsageDescription` | Foreground location |
| `NSMotionUsageDescription` | Uncertainty flagging via CMMotionActivityManager |
| `NSCameraUsageDescription` | Barcode scanning for food log |
| `UIBackgroundModes` → `location` | Keeps location updates firing when app is backgrounded |
| `UIFileSharingEnabled` + `LSSupportsOpeningDocumentsInPlace` | Exposes CSV export files via Files app |

### 4. Capabilities

In **Signing & Capabilities**, add:

- **Background Modes** → check **Location updates**

This matches the `UIBackgroundModes` key in `Info.plist` and is required for the 5-minute background tracker to work.

## Running the App

1. Connect your iPhone and select it as the build target.
2. Press **Cmd+R** to build and run.
3. On first launch, iOS will prompt for **location permission** - choose **Always Allow** for background tracking to function.
4. The onboarding flow will collect:
   - Skin type (I–II or III–VI)
   - Age
   - Clothing preference
   - Starting 25(OH)D baseline (nmol/L)

After onboarding, the main tab interface appears.

## Architecture Overview

### Source files

| File | Role |
|------|------|
| `UvitaApp.swift` | App entry point (`@main`) |
| `ContentView.swift` | Root view; owns `LocationManager`, `DataStore`, `BackgroundTracker` as `@StateObject`; triggers onboarding |
| `Models.swift` | All data types: `DayReading`, `UserProfile`, `FoodLogEntry`, `BodyPartSED`, `VitaminDEngine`, `DiffeyParams`, enums |
| `DataStore.swift` | Persistence (`UserDefaults` JSON), model aggregation, CSV export/recovery, longitudinal Diffey model runs |
| `BackgroundTracker.swift` | 5-minute UV logging loop; indoor/outdoor resolution; manual override logic |
| `LocationManager.swift` | CoreLocation + CoreMotion wrapper; fires `onLocationUpdate` callback on each GPS fix |
| `WeatherService.swift` | Open-Meteo UV fetch + OSM building footprint indoor check |
| `FileLogger.swift` | Append-only CSV audit log (UVlogs, VitaminD, Diet, Corrections, LabeledReadings) |
| `TodayView.swift` | Dashboard: live plasma estimate, start/stop tracking, clothing picker, food log, Log Now |
| `HistoryView.swift` | Longitudinal table with DisclosureGroup per day; summary cards |
| `InsightsView.swift` | Charts and projections |
| `ProfileView.swift` | User settings: age, skin type, oral source, study window, data export |
| `BodyPartView.swift` | Body-part UV exposure bar chart (Lund-Browder coefficients) |
| `OnboardingView.swift` | 5-page first-run setup flow |
| `VitaminDFoodDatabase.swift` | Curated USDA-sourced vitamin D food database (~50 foods) |
| `ColorShims.swift` | `Color.secondaryBackground` / `Color.tertiaryBackground` cross-platform shims |

### Key data flow

```
LocationManager (CoreLocation, ~50m filter)
    └── onLocationUpdate callback
            └── BackgroundTracker.logIfDue()  (throttled to 5 min)
                    ├── WeatherService.fetch()
                    │       ├── Open-Meteo API  →  UVI for current hour
                    │       └── Overpass/OSM API  →  indoor/outdoor bool
                    ├── VitaminDEngine.runModel()  →  plasma nmol/L
                    ├── DataStore.addReading()  →  UserDefaults
                    └── FileLogger.log()  →  CSV files in Documents/
```

### Vitamin D model

The app implements the **Diffey two-compartment pharmacokinetic model**. Each 5-minute reading contributes a SED slice (`VitaminDEngine.uviToSED`). Daily aggregates are fed into `VitaminDEngine.runModel`, which uses the response functions `R_UV(t)` and `R_oral(t)` (biexponential decay) to produce a running plasma 25(OH)D estimate in nmol/L.

Personalisation factors:
- `ageFactor` - linear decline from age 20 (Eq. 10)
- `skinType.factor` - 1.0 for Type I–II, 1/1.35 for Type III–VI (Eq. 9)
- `ClothingOption.bsaPercent` - Lund-Browder body surface area fractions
- `C0` - user-supplied baseline serum level

## External APIs

The app makes two network calls per tracking interval, both unauthenticated and free:

| API | Endpoint | Used for |
|-----|----------|----------|
| Open-Meteo | `https://api.open-meteo.com/v1/forecast` | Hourly UV index, sunrise/sunset |
| OpenStreetMap Overpass | `https://overpass-api.de/api/interpreter` | Building footprint indoor detection |

No API keys are needed. Both calls are made in `WeatherService.swift`. The Overpass query has a 6-second timeout and is skipped when GPS accuracy exceeds 40 m.

## CSV Data Export

The app writes structured CSV files to the app's **Documents** directory, visible in the Files app under **On My iPhone → Uvita**:

| Path | Contents |
|------|----------|
| `UVlogs/YYYY-MM-DD_uv.csv` | Per-reading UV data with body-part SEDs |
| `VitaminD/YYYY-MM-DD_vitamind.csv` | Per-reading plasma estimates |
| `Diet/YYYY-MM-DD_diet.csv` | Food log entries |
| `Corrections/corrections.csv` | Indoor/outdoor override corrections |
| `LabeledReadings/labeled_readings.csv` | Manual "Log Now" readings with labels |

Export projection CSVs (7-day Diffey model output) from **Profile → Export projections to CSV**.

## Oral Vitamin D Sources

Configured in **Profile → Oral vitamin D source**:

| Mode | Behaviour |
|------|-----------|
| Apple Health (auto) | Reads dietary vitamin D from HealthKit |
| Log food in UVita | Manual food log using the built-in USDA database |
| Enter IU/day manually | Fixed daily supplement dose |
| Population average | Uses 5 µg/day (~200 IU), no logging needed |
| Assume 0 | UV synthesis only |

## Tips

- **Always Allow location** is required for background tracking. If you only grant "While Using", readings stop when the app is backgrounded.
- The indoor detector requires GPS accuracy < 25 m to return `true`. In poor-signal environments it defaults to outdoors.
- Use **Profile → Study start date** to exclude historical readings from model calculations without deleting them.
- The **corrections.csv** file is useful for evaluating indoor detection accuracy - it records every manual override alongside the auto-detected value.
- If `UserDefaults` is cleared by the OS, **Profile → Recover readings from CSV** can restore readings from the existing CSV files.
